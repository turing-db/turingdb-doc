---
title: "Submit Change"
sidebarTitle: "Submit a Change"
description: "Submit changes done to the database (just like a commit being submited in git)"
---

<Tabs>
  <Tab title="Cypher">
    ```jsx
    // Submit changes done to the database
    CHANGE SUBMIT
    
    // Checkout to main branch
    checkout
    ```
  </Tab>
  <Tab title="Python SDK">
    ```python
    # Submit changes done to the database
    client.query("CHANGE SUBMIT")
    
    # Checkout to main branch
    client.checkout()
    ```
  </Tab>
</Tabs>

<Note>
  `CHANGE SUBMIT` commits any pending writes itself, so a `COMMIT` right before it is optional. In the Python SDK, call `client.checkout()` afterwards to return to main: the client points at the submitted change until you do.
</Note>

If two changes edit the same node, the second submit reports a conflict, for example `This change attempted to update Node 0 (...) which has been modified on main.` The failed change stays open: fix it and submit again, or discard it with `CHANGE DELETE`. See [Writing data](/query/writing#failed-queries-and-conflicts).
