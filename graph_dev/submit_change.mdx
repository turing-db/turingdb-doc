---
title: "Submit Change"
sidebarTitle: "Submit a Change"
description: "Submit changes done to the database (just like a commit being submited in git)"
---

<Tabs>
  <Tab title="Cypher">
    ```jsx
    // Submit changes done to the database
    CHANGE SUBMIT
    
    // Checkout to main branch
    checkout
    ```
  </Tab>
  <Tab title="Python SDK">
    ```python
    # Submit changes done to the database
    client.query("CHANGE SUBMIT")
    
    # Checkout to main branch
    client.checkout()
    ```
  </Tab>
</Tabs>

<Note>
  `CHANGE SUBMIT` commits any pending writes itself, so you do not need a `COMMIT` right before it. In the Python SDK, `client.checkout()` afterwards is **required**: the client still points at the submitted change, and the next query would fail with `CHANGE_NOT_FOUND`.
</Note>

If two changes edit the same node, the second submit fails with an error such as `This change attempted to update Node 0 (...) which has been modified on main.` The failed change stays open: fix it and submit again, or discard it with `CHANGE DELETE`. See [Writing data](/query/writing#failed-queries-and-conflicts).
