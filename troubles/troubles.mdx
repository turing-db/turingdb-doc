## "Graph outdated" or TuringDB fails to start

After updating TuringDB, you may encounter a **"Graph outdated"** error or TuringDB may fail to start.
This happens when the default graph was created by an older version of TuringDB and its storage format is no longer compatible.

To fix this, restart TuringDB with the `-reset-default` flag:

```bash
turingdb -reset-default
```

This deletes the existing default graph and lets TuringDB recreate a fresh one on startup.

<Warning>This will permanently delete all data stored in the default graph. Make sure to back up any important data before running this command.</Warning>

If you are using a custom turing directory, pass it along:

```bash
turingdb -reset-default -turing-dir /path/to/your/turing/dir
```

## `Invalid response from the server` or `Proto header dataLen does not match chunk payload size`

These two errors mean the client and the server disagree on the protocol. A TuringDB server speaks **either** JSON over HTTP **or** the binary protocol, chosen when it starts:

| Error | Cause | Fix |
|---|---|---|
| `Invalid response from the server: Expecting value...` from `TuringDB(host=...)` | The server was started with `USE_TURING_PROTO=1` (binary mode) but you used the default JSON client | Connect with `TuringDB(type="native", host="localhost", port=6666)`, or restart the server without `USE_TURING_PROTO` |
| `Proto header dataLen does not match chunk payload size` from `TuringDB(type="native", ...)` | The server is a normal JSON server | Use the default `TuringDB(host="http://localhost:6666")`, or restart the server with `USE_TURING_PROTO=1` |

See [client backends](/pythonsdk/reference#client-backends) for details.

## `The request body must be a JSON object`

The server expects each query as a JSON body, `{"query": "...", "parameters": {...}}`. Two common causes:

- **An older SDK against a 3.0.2 server.** Upgrade the Python SDK to the same version as the server: `pip install 'turingdb>=3.0.2'`.
- **A raw HTTP request with the query as plain text.** Send JSON instead, see the [HTTP API](/commands#http-api).

## `REQUEST_TOO_BIG`

A request can be up to 1 MiB. Split a large `UNWIND` into batches, for example 10,000 node-ID pairs per request, or load bulk data from a file with [`LOAD PARQUET`](/import_data/parquet) or [`LOAD JSONL`](/import_data/jsonl).

## `401 Unauthorized`

The server was started with `-auth-on` and your client did not send a valid token. Pass `token="..."` to `TuringDB(...)`, or set the `TURINGDB_AUTH_TOKEN` environment variable. The JSON client raises this as an `httpx.HTTPStatusError`.

---

## `CHANGE_NOT_FOUND` after `CHANGE SUBMIT`

After `CHANGE SUBMIT` the Python client still points at the submitted change. Call `client.checkout()` to return to main before running the next query.

---

## `Cannot perform CREATE outside of a write transaction`

All writes (`CREATE`, `MERGE`, `SET`, `REMOVE`, `DELETE`) must run inside a change. Call `client.new_change()` first, and submit with `CHANGE SUBMIT`. See [Writing data](/query/writing).

---

## A `MATCH` right after a `CREATE` returns no rows

Entities created earlier in a change are visible to a later `MATCH` once you run `COMMIT`. Run `COMMIT` after creating nodes and before matching them to create edges. A `MERGE` finds them without it. See [Writing data](/query/writing#when-you-need-commit-inside-a-change).

---

## `Function 'X' does not exist`

A few functions are not yet available in TuringDB, such as `rand()`, `date()`, `timestamp()` and `elementId()`. In v3, `type()` replaces `edgeType()`. See [Functions and data types](/query/functions) for the full list.
