## Start

Starts the TuringDB server. This is the default command, running `turingdb` without a subcommand is equivalent to `turingdb start`.

```bash
turingdb start [options]
```

### Options

| Flag | Description | Default |
|---|---|---|
| `-demon` | Run TuringDB as a background daemon | off |
| `-p <port>` | Server listen port | `6666` |
| `-i <addr>` | Server listen address | `127.0.0.1` |
| `-turing-dir <path>` | Root Turing home directory | `~/.turing` |
| `-load <graph>` | Load a graph at startup (can be repeated) | |
| `-in-memory` | Run without writing graphs to disk | off |
| `-reset-default` | Delete the default graph before starting | off |
| `-ui` | Launch the built-in visualizer proxy | off |
| `-ui-port <port>` | Visualizer proxy port | `8080` |
| `-auth-on` | Require a bearer token on every request. The token is read from the `TURINGDB_AUTH_TOKEN` environment variable, and must be set when you use this flag | off |
| `-no-vector-mmap` | Read HNSW [vector indexes](/vector-search) into memory at startup instead of memory-mapping their files | off |

With `-demon`, `turingdb start` returns once the server is ready. If the server cannot start, it exits with an error that says why, for example `Could not start the server on 127.0.0.1:6666: bind: Address already in use`, or `TuringDB is already running` when another instance uses the same `-turing-dir`.

### Examples

Interactive mode (default):

```bash
turingdb
```

Daemon mode on a custom port:

```bash
turingdb start -demon -p 7777
```

Daemon mode with the visualizer:

```bash
turingdb -demon -ui
```

Load a graph at startup:

```bash
turingdb -load mygraph
```

Require authentication:

```bash
TURINGDB_AUTH_TOKEN=s3cret turingdb start -demon -auth-on
```

Serve a Node.js application, whose `fetch` refuses the default port (see [Connecting clients](#connecting-clients)):

```bash
turingdb start -demon -p 6686
```

<Note>
  Server logs are written to `<turing-dir>/logs/turingdb.log`. Additional details about an import, such as a `LOAD JSONL`, are written there.
</Note>

### Interactive shell

Without `-demon`, `turingdb start` serves clients **and** opens an interactive Cypher shell. Besides Cypher queries and [engine commands](/query/procedures#commands), the shell has a few local commands:

| Command | Description |
|---|---|
| `cd <graph>` | Switch the active graph |
| `checkout change-<id>` | Work on a change. `checkout <commit>` opens a past commit, and `checkout` returns to the latest commit of main |
| `read <file>` | Run the queries in a file |
| `:param <name> => <value>` | Set a [query parameter](/query/cypher_subset#query-parameters), with the value written as a Cypher expression: `:param label => 'Person'`, `:param ids => [0, 1, 2]`, `:param since => datetime('2024-01-01T00:00:00Z')`. `:param clear` removes them all |
| `SHOW PARAMETERS` | List the parameters set in the shell, with their types |
| `connect <addr> <port>` | Send the next queries to another TuringDB server, for example `connect 127.0.0.1 6666`. `disconnect` returns to the local engine |
| `help` | List the available commands |
| `quit` / `exit` | Leave the shell |

## UI

Launches the built-in graph visualizer.

```bash
turingdb start -ui [options]
```

Once started, open the visualizer at `http://127.0.0.1:8080` (or the port set via `-ui-port`).

### Options

| Flag | Description | Default |
|---|---|---|
| `-ui` | Launch the built-in visualizer | off |
| `-ui-port <port>` | Visualizer port | `8080` |

### Examples

Start TuringDB with the UI:

```bash
turingdb -ui
```

Start TuringDB as a daemon with the UI on a custom port:

```bash
turingdb -demon -ui -ui-port 9090
```

## Stop

Gracefully stops a TuringDB instance running as a daemon. It sends a stop signal through the Unix socket and waits for the process to shut down gracefully.

```bash
turingdb stop [options]
```

### Options

| Flag | Description | Default |
|---|---|---|
| `-turing-dir <path>` | Root Turing directory of the instance to stop | `~/.turing` |
| `-timeout <ms>` / `-t <ms>` | Time to wait for the process to release its lock | `3000` |

### Examples

Stop the default instance:

```bash
turingdb stop
```

Stop an instance running in a custom directory:

```bash
turingdb stop -turing-dir /data/myturing
```

## Environment variables

| Variable | Read by | Effect |
|---|---|---|
| `TURINGDB_AUTH_TOKEN` | server and Python SDK | With `-auth-on`, the token the server requires. The Python SDK sends it as a bearer token when set. The JavaScript SDK takes the token as its `authToken` option |

## Connecting clients

The server speaks TuringDB's binary protocol, on port 6666 unless you pass `-p`. Query it with one of these clients:

| Client | Install | Connect |
|---|---|---|
| [Python SDK](/pythonsdk/reference) | `pip install turingdb` | `TuringDB(host="localhost", port=6666)` |
| [JavaScript SDK](/jssdk/reference) | `npm install turingdb` | `new TuringClient({ url: "http://localhost:6686/query" })` |
| Interactive shell | ships with the server | `turingdb` without `-demon`, or `connect <addr> <port>` from another shell |
| [Visualizer](#ui) | ships with the server | `turingdb -ui` |

- The protocol runs over HTTP/1.1: each query is a request to `/query`, and its result streams back as binary packets, one per HTTP chunk, on a connection kept open for the next query. Standard reverse proxies such as nginx forward it with a plain `proxy_pass`.
- Each query carries the graph, change and commit it runs on, so the server keeps no session for a client.
- A request can be up to 1 MiB, the query text and its parameters together. A larger one is refused with `The request is over the server limit of 1048576 bytes for the request line, headers and body together`. Split large batches, or load bulk data from a file with [`LOAD PARQUET`](/import_data/parquet) or [`LOAD JSONL`](/import_data/jsonl).
- With `-auth-on`, every request needs the token. A missing or wrong one is refused with `Unauthorized: missing or invalid authentication token`.
- Browsers and the `fetch` of Node.js refuse port 6666. For Node.js, start the server on another port, such as `-p 6686`. A web page reaches the server through a proxy on its own origin, see [In the browser](/jssdk/get_started#in-the-browser).
- Upgrade the clients and the server together: a 3.1 client speaks the protocol of a 3.1 server.
