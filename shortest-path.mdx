TuringDB's `shortestPath` statement runs a Dijkstra search from a source set of nodes to a target set of nodes, returning the shortest distance and the path taken based on a numeric edge weight property.

<Note>
  `shortestPath` is a TuringDB statement for weighted shortest paths. For hop-count questions, or when you need the properties along the route, use [variable-length paths](/query/paths).
</Note>

## Sample dataset

The examples on this page use a small railway network. Run the following query to create it:

```jsx
CREATE (asch:Station {name:"Ashchurch"}),
  (bmv:Station {name:"Bromsgrove"}),
  (cnm:Station {name:"Cheltenham Spa"}),
  (dtw:Station {name:"Droitwich Spa"}),
  (hby:Station {name:"Hartlebury"}),
  (psh:Station {name:"Pershore"}),
  (wop:Station {name:"Worcestershire Parkway"}),
  (wof:Station {name:"Worcester Foregate Street"}),
  (wos:Station {name:"Worcester Shrub Hill"})
CREATE (asch)-[:LINK {distance: 7.25}]->(cnm),
  (asch)-[:LINK {distance: 11.29}]->(wop),
  (asch)-[:LINK {distance: 14.75}]->(wos),
  (bmv)-[:LINK {distance: 31.14}]->(cnm),
  (bmv)-[:LINK {distance: 6.16}]->(dtw),
  (bmv)-[:LINK {distance: 12.6}]->(wop),
  (dtw)-[:LINK {distance: 5.64}]->(hby),
  (dtw)-[:LINK {distance: 6.03}]->(wof),
  (dtw)-[:LINK {distance: 5.76}]->(wos),
  (psh)-[:LINK {distance: 4.16}]->(wop),
  (wop)-[:LINK {distance: 3.71}]->(wos),
  (wof)-[:LINK {distance: 0.65}]->(wos)
```

## Syntax

```jsx
shortestPath(sourceSet, targetSet, edgePropName, distanceReturnVar, pathReturnVar)
```

| Parameter           | Description                                                         |
| ------------------- | ------------------------------------------------------------------- |
| `sourceSet`         | Variable bound to the source node(s) via a preceding `MATCH` clause |
| `targetSet`         | Variable bound to the target node(s) via a preceding `MATCH` clause |
| `edgePropName`      | Name of the numeric edge property to use as weight, written as a bare identifier (`distance`), **not** a quoted string. Edges where it is null are skipped |
| `distanceReturnVar` | Output variable name for the total shortest distance. A Double, or an Integer if the weight is an integer |
| `pathReturnVar`     | Output variable name for the path: a flat list of alternating IDs `[node, edge, node, edge, ..., node]` |

## Basic usage

<Tabs>
  <Tab title="Cypher">
    ```jsx
    MATCH (n{name:"Ashchurch"}), (m{name:"Worcestershire Parkway"})
    shortestPath(n, m, distance, dist, path)
    RETURN dist, path
    ```
  </Tab>
  <Tab title="Python SDK">
    ```python
    df = client.query("""
    MATCH (n{name:"Ashchurch"}), (m{name:"Worcestershire Parkway"})
    shortestPath(n, m, distance, dist, path)
    RETURN dist, path
    """)
    print(df)
    ```
  </Tab>
</Tabs>

```
    dist       path
0  11.29  [0, 1, 6]
```

`path` alternates node and edge IDs: node `0`, edge `1`, node `6`.

## Multiple sources or targets

You can pass multiple nodes to the source or target set — `shortestPath` will find the shortest distance across all combinations and return the best one:

<Tabs>
  <Tab title="Cypher">
    ```jsx
    MATCH (n), (m{name:"Worcestershire Parkway"})
    WHERE n.name = "Bromsgrove" OR n.name = "Cheltenham Spa"
    shortestPath(n, m, distance, dist, path)
    RETURN dist, path
    ```
  </Tab>
  <Tab title="Python SDK">
    ```python
    df = client.query("""
    MATCH (n), (m{name:"Worcestershire Parkway"})
    WHERE n.name = "Bromsgrove" OR n.name = "Cheltenham Spa"
    shortestPath(n, m, distance, dist, path)
    RETURN dist, path
    """)
    print(df)
    ```
  </Tab>
</Tabs>

```
   dist       path
0  12.6  [1, 5, 6]
```

If a set matches several source and target nodes, only the single best pair is returned.

## Usage notes

<Warning>
  The variables in the pattern going into `shortestPath` are consumed by the statement, so `RETURN` takes `dist` and `path`. Asking for a pattern variable such as `n` is reported as an error:

  ```jsx
  MATCH (n{name:"Ashchurch"}), (m{name:"Worcestershire Parkway"})
  shortestPath(n, m, distance, dist, path)
  RETURN dist, path, n
  ```

  ```
  ANALYZE_ERROR: Cannot return n after SHORTESTPATH.
  ```
</Warning>

- **Directed.** Outgoing edges are followed. When the target cannot be reached from the source, the query returns zero rows.
- **`RETURN` follows directly.** Put `ORDER BY` and `LIMIT` on that `RETURN`.
- **Reading `path`.** `path` is a flat list of IDs. To get names and properties, map the IDs back with a second query (see below).
- **Where the other nodes come from.** A join can feed an endpoint: `MATCH (x {name: "Bromsgrove"})-[:LINK]->(a), (b {name: "Worcester Shrub Hill"}) shortestPath(a, b, distance, dist, path) RETURN dist, path`.

## Naming the stations along the route

To turn the IDs in `path` back into names, run a second query. The even positions of `path` are nodes:

```python
row = client.query("""
MATCH (a:Station {name: 'Bromsgrove'}), (b:Station {name: 'Worcester Shrub Hill'})
shortestPath(a, b, distance, dist, path)
RETURN dist, path
""").iloc[0]

node_ids = [int(i) for i in row["path"][0::2]]     # the stations, from source to target
names = client.query(f"UNWIND {node_ids} AS x MATCH (n) WHERE n = x RETURN x AS id, n.name AS name")
```

Each station is looked up directly by its ID (see [lookup by node ID](/query/matching#look-up-nodes-by-native-node-id)).

For large graphs prefer `shortestPath` over variable-length paths: variable-length matching enumerates every path.
